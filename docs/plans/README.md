# Plans and Proposals

**Status:** Navigation index
**Scope:** Planning artifacts, proposals, and recovery runbooks.

Plans are not policy and are not an automatic implementation queue. Start from the
[Product Knowledge Map](../0_PRODUCT_KNOWLEDGE_MAP.md), the active [TODO](../../TODO.md), and the
relevant Feature Card. A plan may explain a prior approach, a proposal, or a pending decision; its
own status line defines whether it is active, blocked, implemented, or retained only as history.

Before implementing from a plan, confirm that its assumptions still match the current SSoT,
contracts, and code. Where they conflict, the SSoT and explicit user instruction win. Historical
plans remain here for decision traceability and must not silently restore obsolete routes, models,
or workflows.

The attachment recovery plan is retained as a historical recovery runbook because its migrations
and verification commands remain in the repository. It does not create new attachment policy.
