# SIMPLE-UI-DELIVERY-FLOW — Tahap 4: Build Phase 04d (P4d) — Panel riwayat serah-terima per Feature

**Status:** Disetujui Owner (chat, 2026-10-29); diimplementasikan, lolos tes dan UAT lokal (2026-10-29)
**Breakdown:** [../breakdown.md](../breakdown.md)
**AC phase ini:** AC-4.5 (sudah ada di `product.md`)
**Applicable Policy IDs:** AI-009, AI-013, AUTH-001, CONTRACT-001, DATA-001, TEST-001, UI-001, UI-002, UI-003, UI-004, UI-005
**Prinsip (Owner):** siapa pun yang membuka sebuah Feature bisa menelusuri serah-terima dan pesan antar peran tanpa membuka subtask satu per satu, dan tahu mana yang ditujukan kepadanya.

## 1. Temuan dari kode

| Temuan                                                                                                                                                                                                                            |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Pesan serah-terima sudah tersimpan sebagai `task_comments` dengan `handoff_kind` (P4a, migrasi sudah ada). Tidak perlu migrasi baru; yang belum ada hanya cara membacanya per Feature.                                            |
| Antrean (`attachHandoffMessages`) hanya mengambil pesan terakhir per subtask untuk satu peran; tidak ada query lintas subtask per Feature dan tidak ada paginasi.                                                                 |
| Komentar task dapat dibaca setiap anggota aktif workspace (`requireActiveMember`); `handoffKind` hanya label dan tidak memberi hak (`authorization.md`). Endpoint riwayat memakai batas baca yang sama, jadi tidak ada izin baru. |
| Mention (`task_comment_mentions`) dan penerima serah-terima (assignee subtask, penulis komentar induk pada balasan) sudah ada di data, cukup untuk menurunkan penanda "Untukmu" di server tanpa kolom baru.                       |
| Detail Feature (`FeatureDetailPage`) dan kartu antrean (`RoleAwareWorkQueuePanel`) sudah memuat `featureTaskId`, jadi panel bisa dipasang di keduanya.                                                                            |
